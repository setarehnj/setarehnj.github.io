What sparse autoencoders don’t tell you about a circuit

interpretability
research notes
sparse autoencoders
Working notes on the gap between interpretable SAE features and mechanistic explanations.
Published

August 11, 2026

Sparse autoencoders (SAEs) are appealing because they decompose dense model activations into a sparse dictionary of learned features that are often easier to describe than individual neurons (Bricken et al., 2023; Cunningham et al., 2023).

While reading the SAE literature, there is one distinction I want to keep explicit:

Finding a human-interpretable direction in activation space is not the same as showing that the model uses that direction as a computational variable.

This note is me working through that distinction.

Basic setup

For activations \(x \in \mathbb{R}^d\), a sparse autoencoder learns a sparse latent representation \(f(x)\) and uses it to reconstruct the original activation:

\[ \hat{x} = W_{\mathrm{dec}} f(x) + b_{\mathrm{dec}}. \]

A simple version of the encoder is

\[ f(x) = \operatorname{ReLU}\!\left( W_{\mathrm{enc}}(x - b_{\mathrm{dec}}) + b_{\mathrm{enc}} \right), \]

trained with an objective of the form

\[ \mathcal{L} = \lVert x - \hat{x} \rVert_2^2 + \lambda \lVert f(x) \rVert_1 . \]

The reconstruction term asks the dictionary to preserve the information in the original activation. The sparsity term encourages each input to be represented by relatively few dictionary elements.

SAE variants change both the activation function and the sparsity penalty, so this is best read as the basic picture rather than a definition that covers every SAE.

Interpretability is not yet mechanism

Suppose an SAE feature fires on tokens that all look semantically related. That is evidence that the learned direction captures some regularity in the model’s representation. It does not yet tell me what role that direction plays in the computation.

I see at least three separate questions:

  1. Can I describe the feature? Does its activation pattern correspond to something coherent enough that a human can give it a useful description?

  2. Does manipulating it causally affect the model? If I intervene on the feature, do downstream activations or outputs change in the way the proposed interpretation predicts?

  3. Is this decomposition privileged in any meaningful sense? Would another SAE — a different random seed, dictionary size, or sparsity constraint — recover something recognizably equivalent?

The first question is primarily about interpretability. The second bears directly on causal relevance. The third asks something different: whether the learned decomposition is robust enough to treat its features as more than one convenient coordinate system.

There is also a further jump from a causally relevant feature to a circuit-level explanation. A circuit claim is not just that some feature matters, but that a set of components and their interactions account for a computation. SAE features may provide useful nodes for such an explanation, but learning the features does not by itself identify the causal graph connecting them (Marks et al., 2024).

Why reconstruction isn’t enough

An SAE can reconstruct activations well without recovering the variables that are most useful for explaining the model’s computation. The two objectives ask different questions:

  • Reconstruction: can these features reproduce \(x\)?
  • Mechanistic interpretability: which internal variables explain how the model transforms \(x\) into later computations?

They are related, but not identical. A dictionary could contain directions that are excellent for reconstruction and easy to label, yet still give an inconvenient basis for explaining a particular circuit. Conversely, a feature that looks semantically messy might turn out to be causally important.

Sparsity adds a second tension. Relaxing the sparsity constraint generally gives the SAE more flexibility to reduce reconstruction error, but it also moves the representation away from the sparse regime that motivated the decomposition in the first place. The interesting regime is therefore not simply the point with the lowest reconstruction error.

What I would want to test

Before treating an SAE feature as part of a mechanistic explanation, I would want several kinds of evidence.

Causal intervention

Ablating, suppressing, or amplifying the feature should change downstream behavior in the way the interpretation predicts (Marks et al., 2024). This is achievable: on the indirect-object-identification task, SAE features can localize causally responsible behavior more finely than alternative decompositions (Cunningham et al., 2023). The point is not that SAE features aren’t causal, but that interpretability alone doesn’t show that they are.

Even then, the intervention defines the counterfactual being tested. Zero ablation, mean replacement, resampling, and activation patching do not ask exactly the same causal question, and methodological choices can materially change the resulting localization (Heimersheim & Nanda, 2024; Zhang & Nanda, 2024). An observed effect therefore should not automatically be credited to the semantic label attached to the feature.

Specificity

If a feature is interpreted as representing a concept \(C\), manipulating it should preferentially affect computations involving \(C\), rather than perturbing the model broadly. Otherwise, a large causal effect could reflect disruption rather than understanding.

Stability

I would also want to know how stable the feature is under changes to

  • the random seed,
  • the dictionary size,
  • the sparsity level,
  • the training data, and
  • the SAE architecture.

Perfect one-to-one recovery is probably too strong a requirement — SAEs trained on the same data with different seeds can learn noticeably different features (Paulo & Belrose, 2026). But if an interpretation depends heavily on one particular decomposition, that is important to know before treating the feature as a natural unit of the model’s computation.

The question I’m left with

When I read an SAE interpretation result, the experiment I most want to see is one that reports three things side by side:

Interpretability Reconstruction quality Causal effect
Can we name it? How well does it reconstruct \(x\)? Does intervening do what the name predicts?

A feature becoming easier to name is interesting. A feature becoming easier to name and giving a more faithful causal description of the model would be much stronger.

For now, I think it is useful to treat these as separate achievements, rather than assuming that one establishes the other. Put compactly:

\[ \text{interpretable feature} \;\not\Rightarrow\; \text{causal variable} \;\not\Rightarrow\; \text{circuit explanation}. \]
